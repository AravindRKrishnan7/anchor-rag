# RAG over interview transcripts

## Context
`/chat` can currently only look up structured facts (people, courses, seats) using keyword search. We want it to also answer from what people *said* in interviews, and to find the right passage even when the question uses different words from the transcript ("crew quitting" → "turnover", "losing power" → "blackout"). That needs meaning-based (vector) search, blended with keyword search so exact terms like "ECDIS" or "ballast tank" still win.

## The plan in plain language
1. **Write three short interviews** as text files, each with someone already in the database (Ravi Menon – chief engineer, Priya Nair – crewing manager, Lakshmi Iyer – surveyor). Each file says who it's with, then alternates interviewer questions and the person's answers. I'll deliberately phrase the answers so the test questions can't match them word-for-word.
2. **Add two tables.** `interviews` = one row per transcript file (who, title, date, which file). `chunks` = one row per answer, holding the answer text, who said it, which interview, a 768-number "meaning fingerprint" (embedding), and the name of the model that made it (so if we ever switch models we know which vectors are stale).
3. **Ingestion script.** Reads each file, cuts it into one chunk per answer, asks the local `nomic-embed-text` model (via Ollama) for each chunk's fingerprint, and saves it. Each file is identified by its filename, and its chunks are replaced as a unit, so running the script again updates instead of duplicating. If a file and model haven't changed it's skipped entirely.
4. **New chat tool `search_documents`.** For a question, it runs two searches over the chunks: (a) "closest in meaning" using pgvector, (b) "contains these words" using Postgres full-text. Each produces a ranked list; Reciprocal Rank Fusion merges them by giving each chunk points for how high it ranked in each list (`1/(60+rank)`), so things ranked well by both float to the top. Returns the best 5 with the speaker's name and the interview title.
5. **Test** with questions that share meaning but not vocabulary with the transcripts, confirm the right chunks come back, rerun ingestion to prove no duplicates.

## Files

### `transcripts/` (new, repo root)
`01-ravi-menon-engine-room.md`, `02-priya-nair-crewing.md`, `03-lakshmi-iyer-surveys.md`. Format:
```
person_id: 1
title: Life in the engine room

Interviewer: ...
```

Header lines until the first blank line; then `Speaker: text` paragraphs (continuation lines join the previous turn). ~5–6 answers each. Topics chosen for semantic tests: main-engine failures / blackouts and planned maintenance (Ravi); fatigue, rest hours, crew not re-joining (Priya); corrosion, coating breakdown, buying second-hand ships (Lakshmi).

### `db/init/02-schema.sql` — append (same idempotent `IF NOT EXISTS` style)
```sql
CREATE TABLE IF NOT EXISTS interviews (
    id             integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    person_id      integer NOT NULL REFERENCES people (id) ON DELETE CASCADE,
    title          text NOT NULL,
    interviewed_on date,
    source_file    text NOT NULL UNIQUE,   -- dedupe key for re-ingestion
    content_hash   text NOT NULL,          -- skip unchanged files
    created_at     timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE IF NOT EXISTS chunks (
    id              integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    interview_id    integer NOT NULL REFERENCES interviews (id) ON DELETE CASCADE,
    person_id       integer NOT NULL REFERENCES people (id) ON DELETE CASCADE,
    chunk_index     integer NOT NULL,
    content         text NOT NULL,
    embedding       vector(768) NOT NULL,
    embedding_model text NOT NULL,
    search          tsvector GENERATED ALWAYS AS (to_tsvector('english', content)) STORED,
    UNIQUE (interview_id, chunk_index)
);
-- + HNSW index on embedding (vector_cosine_ops), GIN on search, index on person_id
```
Apply to the running container: `docker compose exec -T db psql -U anchor -d anchor < db/init/02-schema.sql`.

### `app/embeddings.py` (new)
- `OLLAMA_URL` (moved here from `main.py`, which imports it), `EMBED_MODEL = os.getenv("OLLAMA_EMBED_MODEL", "nomic-embed-text")`.
- `embed(texts: list[str]) -> list[list[float]]` → POST `/api/embed` with `input` list, using `urllib` like `ollama_chat` in `app/main.py:334`.
- `embed_documents(texts)` / `embed_query(text)` add nomic's required prefixes `search_document: ` / `search_query: ` (without these, nomic retrieval quality drops noticeably).
- `to_pgvector(vec) -> str` formats `[x,y,...]` for `%s::vector` — avoids adding the `pgvector` Python package.

### `scripts/ingest_transcripts.py` (new; run as `python -m scripts.ingest_transcripts`)
- For each `transcripts/*.md`: parse header + turns; chunks = turns whose speaker isn't `Interviewer`.
- Validate speaker/person_id exists in `people` (fail loudly otherwise).
- One transaction per file, using `app.db.pool`:
  - `INSERT ... ON CONFLICT (source_file) DO UPDATE` the interview, returning id + previous hash.
  - If hash unchanged **and** all its chunks already use `EMBED_MODEL` → skip.
  - Else embed all answers in one batch call, `DELETE FROM chunks WHERE interview_id = %s`, insert new chunks.
- Prints per file: `inserted N` / `unchanged`.

### `app/main.py`
- `search_documents(query)`: embed the query, then one SQL statement:
  - `vec` CTE: top 20 chunks for `embedding_model = %s` by `embedding <=> %s::vector`, with `row_number()` as rank.
  - `fts` CTE: top 20 by `ts_rank` using the existing `SEARCH_ANY_WORD` helper (`app/main.py:278`).
  - Fuse: `FULL OUTER JOIN` on chunk id, `score = coalesce(1.0/(60+vec.rank),0) + coalesce(1.0/(60+fts.rank),0)`, order by score, `LIMIT CHAT_SEARCH_LIMIT` (5).
  - Join `people` (name) and `interviews` (title, date). Return `{"matches": [{chunk_id, person_id, person_name, interview_title, interviewed_on, text, score}]}`.
- Add to `CHAT_TOOLS` (description: "Search interview transcripts for what people said about a topic; use for opinions, experiences, advice") and to `CHAT_TOOL_QUERIES` as `(search_documents, "query", str, None)` — reuses `run_chat_tool` unchanged.
- One sentence added to `CHAT_SYSTEM_PROMPT`: use `search_documents` for what people said in interviews, and attribute quotes to the named person.
- Embedding failures are `URLError`, already mapped to 503 by `/chat`.

### `.env.example`
Add `OLLAMA_EMBED_MODEL=nomic-embed-text` (optional override).

## Verification
1. Apply schema; `python -m scripts.ingest_transcripts` → reports chunks inserted; `SELECT count(*) FROM chunks` ≈ 15–18.
2. Run it again → every file "unchanged"; count identical. Edit one answer, rerun → only that file re-embedded, count still identical.
3. Direct tool check (python one-liner calling `search_documents`) with meaning-only queries, confirming the top hit is from the right person:
   - "Who has talked about seafarers being too exhausted?" → Priya (text says "fatigue", "rest hours")
   - "Has anyone dealt with a ship losing all power at sea?" → Ravi ("blackout")
   - "What should I watch for when buying a used vessel?" → Lakshmi ("second-hand", "coating breakdown")
   - Plus one exact-term query (e.g. a code word only in one transcript) to show the full-text side contributes.
4. `uvicorn app.main:app` then `curl -X POST /chat` with the same questions → `tool_calls` shows `search_documents`, answer names the right person and doesn't invent content.
5. Commit on a branch only if you ask.

## Changes during implementation
- Full-text side of `search_documents` uses `websearch_to_tsquery` (all words must appear) instead of `SEARCH_ANY_WORD`. Matching any single word of a question ("vessel", "watch") in long passages outvoted the correct vector ranking in RRF.
